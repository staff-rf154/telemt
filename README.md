# telemt — рабочий каталог стенда

Здесь лежат файлы, из которых поднимается контейнер `telemt`.

## Состав

| Путь | Что это |
|---|---|
| `docker-compose.yml` | боевой compose, без секции `build` (образ берётся из кэша) |
| `config/config.toml` | конфиг с ключом `[access.users] default` |
| `config/cache/` | кэш публичного IP |
| `.backup/` | эталон тех же файлов, с которого восстанавливается каталог |
| `restore.sh` | восстановление из `.backup/` |

## Восстановление

Каталог дважды очищался извне. Последствие: без `docker-compose.yml` Docker
создаёт контейнер с дефолтами и без монтирования `./config:/etc/telemt`,
поэтому `telemt` под uid 65532 (`nonroot`) не может создать
`/etc/telemt/config.toml` и уходит в бесконечный рестарт:

```
Error: failed to create explicit config at /etc/telemt/config.toml: Permission denied (os error 13)
```

```bash
./restore.sh --check    # состояние каталога, контейнера и наличие ключа
./restore.sh --files    # разложить файлы из .backup/, контейнер не трогать
./restore.sh            # восстановить и пересоздать контейнер
./restore.sh --backup   # обновить .backup из текущих рабочих файлов
```

Ключ не перегенерируется — `config.toml` копируется как есть, поэтому все
существующие клиенты продолжают работать. После правки конфига имеет смысл
выполнить `--backup`, чтобы эталон не разошёлся с боевой версией.

## Требования

- образ `ghcr.io/telemt/telemt:latest` должен быть в локальном кэше: секции
  `build` в compose нет, образ не пересобирается
- каталог `config` и файлы в нём принадлежат uid 65532 (`nonroot` в образе);
  `restore.sh` выставляет это сам

## Где ещё лежат копии

- `/opt/backup/proxy/telemt/` — боевой каталог и исходники проекта в архиве
- исходники проекта (Rust, `Cargo.toml`, `src/`) в архиве `/opt/backup`,
  в боевом каталоге они не нужны
